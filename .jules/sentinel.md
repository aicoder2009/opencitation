## 2025-02-28 - [XSS via unsanitized dangerouslySetInnerHTML]
**Vulnerability:** The application was passing unvalidated HTML variables, specifically `citation.formattedHtml`, to React's `dangerouslySetInnerHTML` prop in multiple components (`src/components/wiki/sortable-citation.tsx`, `src/app/cite/page.tsx`, `src/app/share/[code]/page.tsx`).
**Learning:** This is a classic pattern for Cross-Site Scripting (XSS). If a citation's contents originated from an untrusted source or were maliciously formatted, an attacker could execute arbitrary scripts in a user's session when the citation is rendered.
**Prevention:** Always sanitize any untrusted or dynamic HTML before rendering it in React. In a Next.js (SSR) application, use a library like `isomorphic-dompurify` to safely strip malicious scripts from the HTML payload on both the client and server side without hydration errors.
## 2024-05-18 - Prevent XSS in Markdown Rendering with DOMPurify
**Vulnerability:** The application was using the `marked` library to render markdown files directly into HTML strings, which were then injected into components using `dangerouslySetInnerHTML`. By default, `marked` does not sanitize HTML, which presents a Cross-Site Scripting (XSS) risk if malicious code is embedded within the markdown source.
**Learning:** Even though markdown content might be from "trusted" sources (like internal doc pages or GitHub API results), displaying it using `dangerouslySetInnerHTML` directly from `marked` without sanitization is an unsafe pattern that can result in XSS if an attacker is ever able to manipulate that source (e.g. compromising GitHub releases, or a poisoned internal document).
**Prevention:** Always wrap outputs from `marked` (or any other markdown parser) with `DOMPurify.sanitize()` (via `isomorphic-dompurify`) before rendering the HTML to the DOM. This provides an essential defense-in-depth layer.
