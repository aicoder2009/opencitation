## 2025-02-14 - Fix Cross-Site Scripting (XSS) Vulnerability in Markdown Parsing
**Vulnerability:** The application used `marked` to parse markdown content into HTML, which was then directly rendered via React's `dangerouslySetInnerHTML`. However, `marked` does not sanitize its output by default, opening up vectors for Cross-Site Scripting (XSS) attacks if the input markdown (e.g. documentation files or GitHub release bodies) contained malicious script payloads.
**Learning:** Raw HTML output from markdown parsers should always be treated as untrusted, and must never be directly rendered without sanitization. Even if the content seems internally controlled (like docs), relying on an unsanitized parser inherently introduces a vulnerability that could be exploited if an attacker manages to inject malicious content into those sources.
**Prevention:** Always use a sanitization library, such as `DOMPurify` (or `isomorphic-dompurify` in a Next.js/SSR context), to sanitize HTML before rendering it via `dangerouslySetInnerHTML`. The pattern is `DOMPurify.sanitize(marked(input))`.
