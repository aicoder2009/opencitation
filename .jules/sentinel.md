## 2025-02-28 - [XSS via unsanitized dangerouslySetInnerHTML]
**Vulnerability:** The application was passing unvalidated HTML variables, specifically `citation.formattedHtml`, to React's `dangerouslySetInnerHTML` prop in multiple components (`src/components/wiki/sortable-citation.tsx`, `src/app/cite/page.tsx`, `src/app/share/[code]/page.tsx`).
**Learning:** This is a classic pattern for Cross-Site Scripting (XSS). If a citation's contents originated from an untrusted source or were maliciously formatted, an attacker could execute arbitrary scripts in a user's session when the citation is rendered.
**Prevention:** Always sanitize any untrusted or dynamic HTML before rendering it in React. In a Next.js (SSR) application, use a library like `isomorphic-dompurify` to safely strip malicious scripts from the HTML payload on both the client and server side without hydration errors.

## 2025-02-28 - Prevent XSS in Changelog Page via marked library
**Vulnerability:** The Changelog page (`src/app/docs/changelog/page.tsx`) renders markdown directly from GitHub releases via `dangerouslySetInnerHTML={{ __html: marked(release.body) as string }}` without sanitization. While this comes from GitHub, an attacker who gains access to the repository could post a malicious release body, leading to Cross-Site Scripting (XSS) when viewed by a victim.
**Learning:** The application uses `isomorphic-dompurify` to sanitize HTML inputs (like formatted citations) before rendering them with React's `dangerouslySetInnerHTML`. However, the `marked` library used for Markdown parsing does not sanitize HTML by default. Its output must always be wrapped with `DOMPurify.sanitize()` before being rendered via `dangerouslySetInnerHTML`.
**Prevention:** Always use `DOMPurify.sanitize()` when using `dangerouslySetInnerHTML` with `marked` or any external data source.
